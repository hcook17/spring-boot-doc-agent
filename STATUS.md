- **`scripts/verify_llms_docs.py` + `scripts/test_verify_llms_docs.py`** — mechanically re-runs every documented `git`/`gh` command across `claude/llms/pr-*.md` on each CI run, so a stale or drifted verification command fails the build instead of going unnoticed. Resolves `CONSTRAINTS.md`'s "Integration gaps" item 4. Found and fixed one real instance of the exact drift it now guards against while building it: `claude/llms/pr-8.md`/`README.md` still said PR #8 was open well after it had actually merged (`a0acc76`) — repinned to the merge commit and re-verified.
- **Secret/credential-redaction heuristic** (`scripts/_secret_heuristics.py`) — `spring_signal_scan.py` now flags `redaction_zones` (file/line/heuristic, never the value) for configuration/deployment files; `agents/file-summarizer.md`, `agents/doc-writer.md`, and `doc-taxonomy.md`'s configuration.md notes now all say not to transcribe a flagged line's value. `scripts/check_no_secrets_leaked.py` re-applies the same heuristics to a completed run's own output as a deterministic defense-in-depth check (documented in `SKILL.md` as an optional post-run step). Resolves `CONSTRAINTS.md`'s "Secret/credential leakage" gap, heuristically — stated residual scope, not a guarantee (see that file's entry). Complementary signal for repos where config files are checked-in placeholders rather than real secrets: `spring_signal_scan.py` also records each config file's dotted key *set* (`config_key_sets`, `scripts/_config_keys.py`, no YAML dependency), and `spring_drift_check.py` now distinguishes a structural key change (`config_structure_changed`, expected) from the same keys holding different values (`config_values_only_changed_review_needed`, worth a look).
