# Chapter 13. The Future of Data Systems (themes)

## One-sentence thesis

Unbundling, derived data, and reasoning about correctness remain the long-term design pressure.

## Who this chapter is for

Principals setting multi-year direction for doc-engine.

## What it covers

Where the industry pressure points land for this product.

## When to apply

Roadmaps, major refactors, unbundling decisions (kernel vs adapters).

## Where it shows up in systems

`docs/product-architecture.md`, kernel vs meta split, north-star itself.

## Why it matters

Without a north star, unbundling becomes random file moves (the old `claude/` concentration problem).

## How to use it here

Keep design SoR under `docs/design/`; cite domains; refuse band-aid dual homes.

## Section map

- Data Integration
- Unbundling Databases
- Correctness and Reasoning

### Data Integration

- Integration is derived joins across systems — name SoR per fact.
- Fail if integration LWW-merges two SoRs without a deviation.

### Unbundling Databases

- Compose specialized stores with clear derivation edges.
- Fail if unbundling creates dual writers for the same fact.

### Correctness and Reasoning

- Trust but verify; probabilistic faults beat binary fault models.
- Fail if a gate cannot fail (`rel-gate-needs-witness`).

## Digested claims

- Systems unbundle into SoR + specialized derived serving layers.
- Integration is about honest dataflow, not more LWW.
- Correctness needs explicit reasoning and auditability.
