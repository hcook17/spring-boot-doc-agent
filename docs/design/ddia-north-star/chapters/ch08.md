# Chapter 8. Transactions

## One-sentence thesis

Transactions protect integrity under concurrency — know which anomalies you still allow.

## Who this chapter is for

Authors of concurrent updates to shared artifacts or DB rows.

## What it covers

Isolation and integrity under concurrency.

## When to apply

RMW on baselines, shared STATUS edits, concurrent pipeline writers.

## Where it shows up in systems

DB transactions in target apps; file locks / single-writer conventions here.

## Why it matters

Lost updates look like “random CI flakes.”

## How to use it here

Single writer or explicit transaction; cite lite concept; don’t pretend soft merges are serializable.

## Digested claims

- ACID words are overloaded; name the anomaly you prevent.
- Weak isolation is common and lossy under concurrent RMW.
- Serializability is expensive — use when correctness requires it.
