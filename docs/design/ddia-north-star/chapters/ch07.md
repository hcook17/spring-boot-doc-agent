# Chapter 7. Partitioning

## One-sentence thesis

Partitioning scales by splitting data — skew and cross-partition operations become first-class costs.

## Who this chapter is for

Engineers sharding work (Stage-0 groups, Stage-1 slices, Stage-4 fan-out) and anyone tempted to “fix” capacity by raising thresholds alone.

## What it covers

How work and data are split across nodes/groups; secondary indexes; rebalancing as an ops event.

## When to apply

Capacity and fan-out designs (adoption L2); choosing a partition key; reviewing cross-group joins.

## Where it shows up in systems

`partition_repo`, `capacity_preflight`, `cross_group_edges`, Stage-4 shared evidence pool.

## Why it matters

Wrong partition key creates permanent hotspots and band-aid caches; quiet Stage-1 after partitioned edges can hide Stage-4 merged-pool cost.

## How to use it here

Name partition key and skew plan before coding; measure Stage-1 **max** slice and Stage-4 **upper_bound** shared pool; cite domain `07-partitioning-and-skew`.

### Partitioning and Replication

- Replication copies; partitioning splits — they combine but solve different problems.
- A partition still needs a replication story for durability; do not confuse “more groups” with “more durability.”
- Fail if replication lag / LWW is used to paper over a bad partition key (cite `replication-lag-and-lww`).

### Partitioning of Key-Value Data

- Key choice dominates hotspots; hash vs range trade locality for load spread.
- Hot / celebrity keys overload one partition while peers idle.
- Fail if a key is chosen without an explicit skew / hot-key plan (`partition-key-and-hotspots`).

### Partitioning and Secondary Indexes

- Local secondary indexes → scatter/gather reads; global indexes are another partitioned dataset.
- Cross-partition queries reintroduce the coordination partitioning removed.
- Fail if full-bucket broadcast returns as the default Stage-1 attachment (`secondary-indexes-cross-partition`).

### Rebalancing Partitions

- Rebalancing moves ownership — operational cost, not a free background scrub.
- Planning-target group counts can understate actual groups under skew (`build_groups`).
- Fail if warn thresholds are raised to silence load without measuring Stage-4 shared-pool upper_bound (`rel-partition-bounds-fanout`).

## Digested claims

- Partition key choice dominates hot spots.
- Secondary indexes and cross-partition queries reintroduce coordination cost.
- Rebalancing is an operational event, not free.
- Stage-4 input upper_bound ≠ Stage-1 slice; return payloads are still unestimated.
