# Chapter 14. Building Reliable, Scalable, and Maintainable Applications (closing themes)

## One-sentence thesis

Reliability, scalability, and maintainability are explicit goals — operability and evolvability are how you keep them.

## Who this chapter is for

Every engineer on this project at review time.

## What it covers

The three pillars and how they show up in gates and design.

## When to apply

PR review, capacity work, complexity debates.

## Where it shows up in systems

CI gates, capacity_preflight, agent/tool constraints, docs/design.

## Why it matters

Features that ignore operability become adoption blockers.

## How to use it here

Use playbooks `architecture-decision-review` and `refactor-sequencing`; cite maintainability concept.

## Section map

- Reliability
- Scalability
- Maintainability

### Reliability

- Reliability is continuing to work correctly despite faults.
- Fail if a 'temporary' dual writer is left without expiry / revisit.

### Scalability

- Scalability is handling load growth; measure load parameters honestly (upper_bounds).
- Fail if scale is 'fixed' only by raising warn thresholds without measurement.

### Maintainability

- Operability, simplicity, evolvability — cite domain `05` for how-to.
- Fail if accidental complexity is accepted to avoid naming a SoR.

## Digested claims

- Reliability is continuing to work correctly under faults.
- Scalability is coping with growth — measure load parameters.
- Maintainability splits operability, simplicity, evolvability.
