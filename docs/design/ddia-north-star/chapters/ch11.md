# Chapter 11. Batch Processing

## One-sentence thesis

Batch processing derives large views offline; treat outputs as serving-layer loads, not live SoR writes.

## Who this chapter is for

CI authors, Stage-0 tool authors, anyone regenerating large derived artifacts.

## What it covers

Offline derivation patterns and serving-layer loads.

## When to apply

Rebuilding coverage results, catalogs, certification, docs sites.

## Where it shows up in systems

`_build_catalog.py`, coverage scripts, `build_docs_site`, pipeline batch stages.

## Why it matters

Writing batch outputs back into SoR without a clear writer creates the certification/LWW class of bugs.

## How to use it here

Inputs immutable or versioned; outputs regenerated; cite `rel-batch-feeds-serving` / `rel-sor-feeds-views`.

## Section map

- Batch Processing with Unix Tools
- Batch Processing in Distributed Systems
- Batch Processing Models
- Batch Use Cases

### Batch Processing with Unix Tools

- Compose small filters over immutable inputs; stdout/files are derived views.
- Hermetic CI fixtures are the small-batch analogue here.
- Fail if a “unix pipeline” mutates the SoR in place without versioning.

### Batch Processing in Distributed Systems

- Partitioned map/reduce style jobs amplify partition-key skew (cite domain `07`).
- Fail if distributed batch cost is estimated only from Stage-1 slices while Stage-4 merged pools dominate.

### Batch Processing Models

- Materialize then load; avoid live row-at-a-time SoR writes from bulk jobs.
- Immutable inputs enable safe reprocessing and audit.
- Fail if freshness is unspecified yet a stream is rejected “because batch is simpler” without evidence.

### Batch Use Cases

- ETL, training, reconciliation, catalog rebuilds, coverage corpora.
- Repo: catalog build, FP fixtures, certification regeneration.
- Fail if a use case invents a second SoR for convenience (`dev-certification-derived-view`).

## Digested claims

- Batch fits bulk transforms with lagged freshness.
- ETL is derivation from operational SoR to analytical/serving views.
- Serve derived data via stage+load, not live row writes from batch into SoR.
- Immutable inputs enable safe reprocessing.
