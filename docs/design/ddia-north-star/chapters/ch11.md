# Chapter 11. Batch Processing

## One-sentence thesis

Batch processing derives large views offline; treat outputs as serving-layer loads, not live SoR writes.

## Who this chapter is for

CI authors, Stage-0 tool authors, anyone regenerating large derived artifacts.

## What it covers

Offline derivation patterns and serving-layer loads.

## When to apply

Rebuilding coverage results, catalogs, certification, docs sites.

## Where it shows up in systems

`_build_catalog.py`, coverage scripts, `build_docs_site`, pipeline batch stages.

## Why it matters

Writing batch outputs back into SoR without a clear writer creates the certification/LWW class of bugs.

## How to use it here

Inputs immutable or versioned; outputs regenerated; cite `rel-sor-feeds-views`.

## Digested claims

- Batch fits bulk transforms with lagged freshness.
- ETL is derivation from operational SoR to analytical/serving views.
- Serve derived data via stage+load, not live row writes from batch into SoR.
- Immutable inputs enable safe reprocessing.
