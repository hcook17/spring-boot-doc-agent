# PR #12 — Add a heuristic secret-redaction layer for the doc-generation pipeline

## Summary

Closes `CONSTRAINTS.md`'s "Secret/credential leakage into generated docs" confidentiality gap with two complementary mechanisms. **(1) Value-content heuristic:** `scripts/_secret_heuristics.py` (shared, deterministic — password/secret/token/credential-shaped keys paired with non-placeholder values, plus AWS access-key-ID and PEM private-key patterns); `spring_signal_scan.py` records `redaction_zones` (file + line + heuristic name, never the value, `schema_version` bump) for config/deployment files; `agents/file-summarizer.md` and `agents/doc-writer.md` both instructed never to transcribe a flagged line's value (doc-writer needed its own instruction since it has direct `Read` access and can bypass file-summarizer's redaction); `scripts/check_no_secrets_leaked.py` re-runs the same heuristics against a completed run's own output as defense in depth. **(2) Structural config-key-set drift**, added afterward based on the repo owner's real config architecture (checked-in placeholders, real values injected at deploy time — so whether a config file's *key set* changed matters more than whether a value looks secret-shaped): `scripts/_config_keys.py` (indentation-stack YAML/properties key-path extraction, no PyYAML dependency); `spring_drift_check.py` gains `config_structure_changed` vs. `config_values_only_changed_review_needed` classification for configuration/deployment files instead of the old generic fallback.
