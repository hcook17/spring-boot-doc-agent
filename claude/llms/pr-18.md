# PR #18 — Fix infinite-regress bug in claude/llms/ coverage enforcement

## Summary

`check_llms_coverage.py` (PR #16) had a structural bug: a PR that adds a missing `pr-N.md` is itself a newly-merged PR with no `pr-N.md` of its own, since a PR can't document its own merge commit before that commit exists — happened for real, twice (PR #16, then PR #17, each merged and immediately flagged by the check they'd just satisfied). Fixed two ways: **(1)** `claude/llms/README.md` now documents a convention — a PR touching `scripts/`/`agents/`/`skills/`/`references/` should add its own `pr-N.md` in the same PR, pinned to its head commit (the pattern `pr-13.md` already demonstrated pre-merge, now written down as a rule). **(2)** `scripts/check_llms_coverage.py` gains `most_recently_merged()`, exempting the single most-recently-merged PR (by `mergedAt`, not PR number — GitHub PR numbers are assigned at creation, not merge order) from both the missing-doc and stale-state checks, bounding the real requirement to "covered before the *next* PR merges" instead of the impossible "covered before this PR's own CI run finishes." `scripts/test_check_llms_coverage.py` grew from 7 to 14 tests, including a new `MostRecentlyMergedTest` class and cases proving the exemption shifts forward rather than creating a permanent hole. Also bundles `claude/llms/pr-17.md` (itself an instance of the same regress) so PR #17 didn't become newly exposed once this PR became the new "most recent."

This file itself is a live demonstration of the fix working as designed, not a gap: PR #18 was deliberately exempt (as the newest merged PR) at the moment it merged, needing no `pr-18.md` yet — then PR #19 merged after it, the exemption shifted forward, and `check_llms_coverage.py` correctly flagged PR #18 as needing this file. Written now, closing that cycle.
