# PR #28 — Sync status docs, fix ast-grep test-killing bug, resolve bounded JPQL lineage

## Summary

Three related pieces of work reviewing `CONSTRAINTS.md` against the repo's actual current state, from one session:

1. `STATUS.md` and steering-prompts `03`/`04`/`08` had gone stale relative to `claude/session-log.md` — dependency pinning, run-manifest telemetry, and the `references/doc-taxonomy.md` path were already resolved but still described as pending/wrong.
2. `find_ast_grep()` called `sys.exit(1)` directly, silently killing the whole test process (not just one test class) whenever `ast-grep` was missing, since `SystemExit` isn't caught by `unittest`'s `setUpClass` handler. Now raises `AstGrepNotFoundError`, an ordinary exception; the three CLI entry points that call it catch it explicitly to preserve the original stderr-message/exit-1 behavior.
3. JPQL `@Query` values never got SQL-lineage extraction, even though `entity_table_map` already had everything needed for the common single-entity case. `resolve_jpql_to_lineage()` now closes that case; joins, association traversal, JPQL-only functions, entity-name overrides, polymorphic `FROM`, and embedded keys remain explicitly out of scope.
