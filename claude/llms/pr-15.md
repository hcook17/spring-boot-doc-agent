# PR #15 — Pin ast-grep-cli, sqllineage, pathspec via requirements.txt

## Summary

Adds `requirements.txt` at the plugin root, pinning the three previously-unpinned third-party dependencies with compatible-release specifiers (`ast-grep-cli~=0.45.0`, `sqllineage~=1.5.8`, `pathspec~=1.1.1`), verified against current PyPI versions. Updates `.github/workflows/ci.yml`'s install step to `pip install -r requirements.txt`. Marks `CONSTRAINTS.md` item 4 and `MATURITY_ASSESSMENT.md`'s "Dependency reproducibility" row/adoption-gate item resolved — closing a gap PR #14's fresh-environment finding had reclassified as blocking (`test_capacity_preflight.py` failed outright without `ast-grep`; `test_spring_signal_scan.py` failed 7/32 without `sqllineage`). Documents but does not fix a residual robustness gap found while verifying: `SpringSignalScanTest.setUpClass` calls `find_ast_grep()`, which does `sys.exit(1)` when the binary is missing — `unittest` doesn't catch `SystemExit` cleanly inside `setUpClass`, so with all three dependencies absent the suite crashes outright instead of reporting clean per-test failures. Also logs a `claude/tool-quirks.md` entry about two shadowing `ast-grep` installs (cargo/npm at `0.44.1`, pip-installed at `0.45.0`) on this dev machine's `PATH`.
