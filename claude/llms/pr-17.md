# PR #17 — Add claude/llms/pr-16.md (closes the recursive coverage gap)

## Summary

Follow-up to PR #16. `check_llms_coverage.py` correctly flagged PR #16 itself as a coverage gap once merged — no `pr-16.md` existed yet, since a PR can't document its own merge commit before that commit exists. This was named explicitly as the immediate next step in PR #16's own description and session-log entry, not a surprise. Adds `claude/llms/pr-16.md`, hand-verified against merge commit `1e6467b`. Also fixes a script-parseability issue found while verifying: `pr-16.md`'s claim 5 originally used a bare `grep -c ...` to assert absence, which exits non-zero on a zero-count match (correct `grep -c` behavior, but `verify_llms_docs.py` reads any non-zero exit as failure) — reworded to `grep -c ... || true` so the claim is both accurate for a human reader and auto-verifiable.

**Note on the pattern this file is itself an instance of:** merging this PR creates the exact same gap one PR later — `pr-17.md` (this file) didn't exist until after PR #17 merged, so `check_llms_coverage.py` was red against PR #17 immediately after merge, exactly as it was against PR #16. This is a structural property of the convention, not a bug introduced by this PR: as long as documenting a PR requires its own merge commit to exist first, there will always be exactly one most-recently-merged PR that's momentarily uncovered until a follow-up lands. Worth a real design decision (see `claude/session-log.md`) rather than another one-off backfill.
