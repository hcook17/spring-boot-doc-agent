# PR #32 — Execute the mirror-back, and finish #31's index debt

## Summary

Follow-up to #31, which **merged at its pre-patch tip (`d2b42ec`)**, so none of the mirror-reconcile content reached `main`. The result was a live inconsistency: `main` documented a fork check as outstanding and a mirror-back as owed, while the project side was already mirrored and verified.

Two commits.

### `945401f` — execute the mirror-back, and replace inference with a content diff

Every project copy of `00`–`06` was diffed against *every* historical revision of its repo counterpart, rather than inferring divergence from commit counts. Findings:

- `02` was byte-identical to the current repo file — it needed no write at all.
- `06` matched modulo a missing final newline, which was absent on the **repo** side, not the project's.
- `03` and `04` matched exactly at `c65d89e`.
- `00`, `01` and `05` matched *no* revision, because the import commit `8bb2404` rewrote them rather than copying them — so those three were never in sync at any point, and were two revisions behind rather than one.

No project copy holds an edit that is not either an exact ancestor of the repo file or the pre-import original. So the two sides had **not** forked, and the overwrite was safe. All six executed and verified by reading each back and comparing bytes.

This commit also corrects `06-wiredrift-check-task-prompt.md`'s `status:` frontmatter — stale since PR #3, and flagged three separate times in `claude/session-log.md` without being fixed — and adds its missing final newline, the only file under `claude/steering-prompts/` lacking one.

### `c9bfb83` — `claude/llms/` index work

Adds `pr-31.md` for #31 as it actually merged (three commits, not the four an earlier draft claimed), corrects two rows that had gone false, and documents two `verify_llms_docs.py` authoring rules in the README where the next author will read them.

## The manifest table is left as published

#31 shipped a mirror-back manifest wrong in two rows — it inferred each prompt's action from commit counts, when `02` needed no overwrite and `05` was two revisions behind rather than one.

**That table is not corrected here.** It is annotated in place as superseded, and the verified manifest lives in the new entry. Under the append-only convention a merged entry is historical record; rewriting it would be editing published history. An earlier version of this branch *did* correct it in place — which was right while `4dc182c` was unmerged, and wrong the moment it shipped. The rule worth carrying forward: **an append-only entry may be edited freely until it merges, and never after.**

Claims 4 and 5 below check both halves of that: the annotation is present, *and* the original wrong table is still intact.

5. **Claim: and the original, wrong table is still intact underneath it.** This is the half that matters: an annotation plus a quietly-corrected table would defeat the point.

   These are **positive assertions of the wrong content**, not absence checks on the wording a correction might have used. An absence check only catches a rewrite phrased the way its author anticipated — someone fixing the rows with a different column, value, or header passes it while violating its intent. Asserting the exact bytes that must still be there is total; asserting the absence of one anticipated replacement is not. (The patterns use `.` where the row has a backtick, since a command may not contain one.)

   **Each row is asserted individually, and each command fails when its own row changes** — so a failure localizes to a row instead of reporting only that *something* moved. A single aggregate hash would detect the same set of changes without saying which row caused it.

   `git show c9bfb83:claude/session-log.md | grep -c 'Repo commits since the initial import'`
   Expect: `1` — the original commit-count column header, whose inference produced the two wrong rows.
   `git show c9bfb83:claude/session-log.md | grep -c '00-shared-research-standards.md. | .5bd750b., .e0200df. | Overwrite'`
   `git show c9bfb83:claude/session-log.md | grep -c '01-testability-research-prompt.md. | .3eb1551., .3254d67. | Overwrite'`
   `git show c9bfb83:claude/session-log.md | grep -c '02-pluggability-research-prompt.md. | .c65d89e. | Overwrite |'`
   `git show c9bfb83:claude/session-log.md | grep -c '03-constraints-research-prompt.md. | .c65d89e., .824b3b7. | Overwrite'`
   `git show c9bfb83:claude/session-log.md | grep -c '04-analytics-logging-research-prompt.md. | .c65d89e., .824b3b7. | Overwrite'`
   `git show c9bfb83:claude/session-log.md | grep -c '05-clarity-delivery-trust-research-prompt.md. | .8b1cc65. | Overwrite |'`
   `git show c9bfb83:claude/session-log.md | grep -c '06-wiredrift-check-task-prompt.md. | none since .f38e8df. (creation) | \*\*No action\*\*'`
   Expect for each: `1`. Rows 3 and 6 in that list are the two known-wrong ones — `02` was already byte-identical and needed no overwrite; `05` was two revisions behind, not the one its commit list implies.

   `git show c9bfb83:claude/session-log.md | grep -c '^| .0[0-6]-' | grep -qx '7'`
   Expect: no output, exit 0 — **exactly** seven manifest rows, so an added or deleted row fails too. This one is written to fail rather than to print, for the reason in the note below.

   > **`Expect:` values are not machine-checked.** `evaluate()` grades on exit status alone — it never reads the `Expect:` line except to spot "no output". So `grep -c` returning `7` passes a claim that says `1`; the number is verified by a human reading it, and by nothing else. That makes `grep -c` a *presence* check mechanically, not a *count* check. Where a count actually matters, pipe it into something that fails — `| grep -qx '7'` above exits 1 on any other value. This applies to the whole corpus, not just this claim, and is why the row-count assertion is written differently from its neighbours.

   **The rows are deliberately not annotated individually.** Marking each wrong row in place would alter published line content, which is the thing this whole decision avoids — and it would break the hash above. The supersede blockquote sits directly above the table instead: an insertion between blocks, leaving every existing line byte-identical.

    (Prose here deliberately names no git subcommand in backticks — see the third rule in `claude/llms/README.md`'s "Writing the commands". An earlier draft of this paragraph said it three times, and the verifier executed each one against the live repo.)
