# PR #48 — Verified testing/security anchors, cited from steering prompt 10

## Summary

One commit, documentation only.

Prompt `10` §5 anchors *Designing Data-Intensive Applications* the useful way — *"the epub is in the project; do not re-derive these, cite them."* There was no equivalent for testing or security, and the cost showed as re-derivation twice over: test non-vacuity re-verified by hand in PR after PR, and an RCE (`verify_llms_docs.py` piping LLM-authored markdown to `bash -c` with `GH_TOKEN`) that was found, reproduced and deleted correctly — but whose defect class has a standard industry name this repo never reached for, because it had no security vocabulary on hand.

Adds `claude/testing-security-anchors-2026-07-25.md` (the research) and a new §6 to `10-review-persona-and-standards.md` (the citable short form).

Researched to `00`'s bar: arXiv confirmed to resolve *and* to say what is claimed of it, GitHub filtered on stars **and** push recency together, every claim tagged verified-from-a-primary-source-I-opened versus not.

## The one argument worth carrying forward

**Anderson's *Security Engineering* 3e is the DDIA analogue, and not only on merit — the full text is free** at `cl.cam.ac.uk/~rja14/book.html`. That is precisely why DDIA works as an anchor in `10` §5 and a paywalled book would not: an anchor you cannot open is a paraphrase waiting to drift. Google's *Building Secure & Reliable Systems* has the same property and covers reliability.

## Recorded so it is not overclaimed later

Three limits are stated in the doc itself rather than discovered by the next reader:

- `arXiv:1704.08412` (82,447 projects; **only 17% had any tests**) does **not** cite Meszaros. It supports "these patterns are unevenly adopted", not "it validates the xUnit catalogue."
- OWASP LLM category **names** are safe to cite; the **`LLMxx` numbers are not** — the project page presents 2025 as current while the retrieved content enumerated v1.1 identifiers, and 2025 renumbers.
- `xunitpatterns.com` is HTTP-only and could not be fetched, so the free catalogue is second-tier here. `00`'s DeepWiki cross-check was **not** run for `mutmut`/`gitleaks` — recorded as an open frontier rather than implied.

Also assessed and **declined**: OIDC. Nothing to attach to — 0 repo secrets, 0 releases, 0 tags, and the plugin ships as a git checkout rather than a built artifact. The trigger conditions are recorded instead, because the default path at each (a stored PyPI token) is the insecure one.
