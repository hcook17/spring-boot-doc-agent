# PR #16 — Add claude/llms/ coverage check; backfill pr-9..15.md; fix stale pr-13.md

## Summary

`verify_llms_docs.py` only re-runs commands inside `pr-*.md` files that already exist — it can't notice a `pr-N.md` that was never written, or a stale frontmatter `state:` field. A `gh pr list --state merged` audit (prompted by a user question about why `claude/llms/` creation isn't automated) found six merged PRs — #9, #10, #11, #12, #14, #15 — with no `pr-N.md` at all, and `pr-13.md` itself stale (`state: OPEN` in frontmatter, though PR #13 had actually merged at `e8dbe89a`). All six backfilled, each hand-verified against its real merge commit before being written; one bad claim of that verification pass was itself caught and fixed before finalizing (`pr-9.md`'s original "Expect: no output" wording didn't match the command's real output — a trailing stat-summary line). `pr-13.md`'s `state`/`merge_commit` fields corrected. Adds `scripts/check_llms_coverage.py` (+ `scripts/test_check_llms_coverage.py`, 7 tests) — fails CI if a merged PR has no corresponding `pr-N.md`, or if one exists with a `state:` that doesn't match `gh pr list`'s real state, using one `gh` call for both checks. Wired into `.github/workflows/ci.yml` as two new steps. `CONSTRAINTS.md` item 4 updated with an addendum naming this as a second, distinct drift shape from the residual gap already documented there.

This file itself closes the recursive edge case named explicitly in this PR's own description and session-log entry: once merged, PR #16 becomes a new coverage gap under the exact convention it introduces, until its own `pr-16.md` exists.
