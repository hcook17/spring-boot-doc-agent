## Summary

Seven commits. The ask was "agents must use ast-grep, not grep"; the property actually worth defending is that every `[Evidenced — path:line]` claim rests on a rule **known to fire on real code**. A rule set can be entirely ast-grep and still be full of holes, so the mandate and the coverage invariant ship together.

Measured against the real Spring service in the working tree, using this repo's own rules:

| | before | after |
|---|---|---|
| rules firing | **10 of 23** | **17 of 29** |
| `testing__import` | 0 | **1027** |
| newly visible hits | — | **~1,400** |

Thirteen rules returned zero, and nothing in the repo could distinguish *"this codebase has no Kafka"* from *"this rule is broken"*. `testing__import` was named as though it covered test imports generally while its regex matched testcontainers only, so all 16 `org.springframework.boot.test` imports fell into the generic `references` bucket.

## The instrument was wrong first — the part a reviewer should weigh most

Two of the numbers first reported in this work were wrong, and both were caught by measurement rather than review.

**A structurally valid ast-grep pattern returns zero without erroring.** `-p '@Column'` reported **0** against a corpus holding **122** `@Column(name = "...")`, because a marker annotation and an argument-bearing one are disjoint node shapes. `@Table` (really 43) and `@Query` (really 198) were briefly written up as absent on the same basis. Every rule in `spring_ast_grep_rules.yml` that can take arguments now lists both forms, and the lesson is stated in the two agent prompts that search.

**"615-file service" was wrong and reached a commit message.** The corpus is **624** `.java` files; 615 was the `references__package` hit count — files carrying a `package` declaration — mistaken for a file count. The figure predates this branch (`MATURITY_ASSESSMENT.md`, `STATUS.md` and `CONSTRAINTS.md` all carry it, dated 2026-07-24), so only the occurrences introduced here were corrected, by removing the decorative count rather than replacing one stale number with another.

Neither would have been caught by enforcing the tool. That is the argument for the rest of this PR.

## Enforcement is two controls, because they fail differently

- **Check F** in `check_repo_claims.py` — static, unbypassable, CI-only. Fails the build if any `agents/*.md` declares `Grep`, or declares `Bash` without a scoped allowlist entry.
- **`hooks/deny_text_search.py`** — a `PreToolUse` hook catching what static inspection cannot see: an agent shelling out to `grep` through `Bash`. **Verified to fire for subagents**, which the Claude Code docs do not state either way.

A subagent's `tools:` field accepts bare tool names only and cannot express `Bash(ast-grep:*)`, so the allowlist in the committed `.claude/settings.json` is load-bearing rather than convenience — `doc-writer` fans out fourteen ways in parallel.

The hook blocked its own author mid-session: a heredoc carrying prose that began with the word `grep` was tokenized as a command. Fixed by stripping heredoc bodies before tokenizing, with a regression test, rather than by loosening the matcher.

## Coverage as an invariant, not a report

`rule_coverage.py` fails the build if any rule matches nothing in the committed `scripts/rule_fixtures/` corpus — *a rule nobody can make fire is not coverage*. A second mode backtests a real repository and ratchets `rule_coverage_baseline.json`; that corpus is ~101MB and untracked, so it is measured on a dev machine and only the baseline is committed. That split is why the gate can run in CI at all.

## The set, and what moved it

`set_delta.py` answers the question `spring_drift_check.py` does not: **was this change the one anyone predicted?** Drift-check reports precisely that a citation moved. Nothing classified the movement, so reviewing a delta was a human squinting at a count — the same defect `stage0_oracle_compare.py` exists to fix for recall.

A relation states which movements were expected; **the residue is the finding**, never the size of the delta. Demonstrated on the fixture corpus: adding `@Timed` fails `unchanged`, naming `ApiSurface.java [observability__timed] @Timed`, and passes `confined_to_rules(["observability__timed"])`. Same delta, two verdicts.

Members compare under `drift_match_normalizers.tokens` rather than the `first_line` status quo, because #50 measured that: 0/208 false positives against 2/208, neither missing a real change.

`test_metamorphic.py` drives it across **type** (Java, `.gradle`, `.properties`, CRLF, BOM, malformed, empty, unicode paths) and **velocity** (one edit, bulk rename, sustained churn, append-only growth, mass deletion, rescan, whole-tree duplication). It closes two bounds `test_drift_normalization` states it does not cover — *"Only Java is perturbed"* and *"No encoding or line-ending perturbation"* — and asserts **idempotence** and **locality**, words that appeared in no other suite.

Three of its assertions failed on first run and all three were worth having. Two were the tests being wrong: adding a `.gradle` file **does** add a member, a filename-classified one, so the relation is confinement rather than `unchanged`. The third independently reproduced the defect `CONSTRAINTS.md` already carries as flagged-and-unresolved — the stored match is only a node's first line, so wrapping annotation args moves the member. It is asserted in the direction that is true today, so **it fails if the defect is fixed** and should then be deleted rather than adjusted.

## Mechanised non-vacuity

This repo's standing rule is that a gate which cannot be shown to fail is not a gate, and three documents record that it is satisfied by hand — `skills/directional-tests/SKILL.md`, steering prompt `10`, and `testing-security-anchors`, which puts it plainly: *"mutation testing, executed by a human, once, with no artifact proving it was ever done."* The ritual was performed at least four times while this branch was written and the evidence deleted each time.

`mutate.py` applies a defect to a copy of the **tracked** tree and runs the one suite that should notice. **7/7 killed.** Tracked-only keeps the copy small and keeps a concurrent session's untracked work out of the run — the same reasoning `check_code_quality.py` gives for measuring tracked files only.

**Not mutmut**, and the reason is not preference: it mutates Python, while four of the seven defects live in markdown frontmatter, YAML and CI config, where it scores zero. It remains the right complement for the pure-Python modules and is not replaced here.

Three mutators locate their target with `ast-grep --rewrite` so reindenting cannot silently detach them; the four that stay literal each say why, and `RegistryAnchorsTest` fails the build when a literal anchor drifts.

## Two assertions in this PR's own code were wrong and are corrected in it

- **`ast-grep --update-all` does not exit 0 when its pattern matches nothing.** It exits **1** — indistinguishable from a real failure. A docstring claiming otherwise was written from search-mode behaviour and disproved by a test minutes later. The applier now decides on whether the file moved, which also survives a change in that behaviour. Logged in `claude/tool-quirks.md`.
- **The validity gate found a bug in itself.** `scan()` walks a nonexistent directory to completion and returns well-formed empty buckets, indistinguishable from a repo that genuinely contains nothing — comparing against it would score as *"everything was removed"*. The test asserting it raises is what caught that.

## The ratchet caught this change, and was not weakened to pass

Adding a sixth branch to `scan()`'s classification chain pushed it from 89 statements / complexity 30 to **94 / 31**, breaking the committed ratchet. Extracting the chain into `_classify_non_java_file` took it to **67 / 20** — below where it started. The baseline was regenerated **downward**, which tightens it; raising the ceiling would have hidden exactly the growth the ratchet exists to see. `hooks/require_hardened_tests.py` now says so in its denial text.
